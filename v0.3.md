# MacanOS v0.3 — functional infotainment

Base: `3edccf5`, development branch `macanos/v0.3`. The v0.2 two-screen shell,
typography, media panel, layouts and read-only diagnostics remain. No factory
controls, physical CAN, audio integration or NaviRider interface were added.

## Implemented capabilities

- Real OpenStreetMap raster tiles in a pan/zoom Web Mercator viewport, two
  concurrent downloads maximum, bounded queue/cache, identifying User-Agent,
  HTTP freshness/ETag revalidation, retry handling and linked attribution.
- A separate offline XYZ PNG-pack loader with explicit source attribution.
  **No offline geographic coverage is bundled.** It needs a licensed local pack.
  Public OSM viewport cache is not treated as a downloadable offline pack.
- One backend `navigationManager`, exposed through OCTAVE's existing protocol 3,
  carries GPS fixes, proposals, accepted destination and display-unit preferences.
  GPS has a C++ provider interface; the current implementation is explicitly
  simulated near San Francisco. It is not a Macan dynamics or GNSS hardware model.
- Passenger Search accepts coordinates and saved places offline. An explicitly
  configured Nominatim-compatible endpoint supports place-name search. Requests
  are explicit, not autocomplete, globally throttled per backend (at least 1.1 s
  apart) and cached for 24 h, bounded to 32 queries with five results per query.
- Passenger **Send to driver** creates a proposal. The driver accepts or dismisses
  it. Acceptance persists the target and updates the map marker on both clients.
  Locate follows simulated GPS; Target centers on the accepted destination.
- Persistent OCTAVE SQLite trips using a dedicated simulator profile. Journey
  lists recorded trips and opens summaries with distance, duration, peak speed,
  peak coolant and sample count. SQLite, summaries, recovery and recording reuse
  upstream TripRecorder/TripStore; no second trip database was introduced.
- Filterable media library and shared now-playing/progress/volume state. Library
  reads suppress list-change emission to avoid a refresh feedback loop.
- Backend-owned **US defaults (mph, °F)** or metric (km/h, °C), persisted and shared
  across displays. Raw telemetry/storage units stay unchanged. Unknown values
  remain unavailable rather than becoming zero.
- Explicit backend-offline, telemetry-stale, GPS-unavailable/stale, map coverage
  and search error states. The two frontend processes remain independent.

**Not implemented:** route calculation, turn instructions, spoken guidance, ETA,
route transfer, GNSS hardware drivers, MBTiles/vector-pack import or OEM controls.
A destination marker is not a route. The interface labels this explicitly.

## Map solution evaluation

| Candidate | Evaluation | v0.3 decision |
| --- | --- | --- |
| Qt Location 6 / OSM plugin | Installed Qt 6.8.2 Location/Positioning and the separate OSM plugin. A real QML runtime probe reached `mapReady: true` under the workspace's software renderer. Custom provider URLs, disk cache and offline-directory parameters exist. Qt Location carries Qt's LGPL/GPL/commercial terms; provider rights remain separate. | Viable future renderer. Not rejected as unsupported. |
| Qt Quick + explicit raster cache | Uses existing Qt Gui/Network/Quick, straightforward software rendering and explicit separation between online viewport caching and licensed offline sources. No additional runtime Qt module needed by MacanOS. | Implemented and tested with real OSM imagery. It is a functional map viewer, not the earlier illustrative canvas. |
| Native vector renderer / MapLibre integration | Better potential for regional offline vector data, but needs additional renderer, style, fonts and data licensing decisions. | Deferred; not claimed integrated. |

Official references reviewed on 2026-11-04:

- [Qt OSM plugin parameters](https://doc.qt.io/qt-6/location-plugin-osm.html)
- [Qt Location licensing](https://doc.qt.io/qt-6/qtlocation-index.html#licenses-and-attributions)
- [OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/)
- [Nominatim usage policy](https://operations.osmfoundation.org/policies/nominatim/)
- [OSM copyright/data licensing](https://www.openstreetmap.org/copyright)

The public OSM raster endpoint needs no API key, but is best-effort and has no
service guarantee. Its use here is limited to actively viewed tiles, without
prefetch or bulk-download controls. Cache freshness honors server max-age, with
seven days as the fallback. A 100 MiB ceiling stops additional downloads instead
of evicting fresh cache entries. Raw downloaded tiles are not committed to Git.

Offline-region downloads from the public OSM service are prohibited. Use a
self-hosted source or supplier that grants offline rights, and provide its XYZ
pack separately. Cached online tile revisits and licensed offline maps are
separate code paths. Do not use the capture tool to scrape regions or zoom stacks.

Nominatim data is ODbL. Its public endpoint needs no API key, but requires an
informed provider choice, proper identification/attribution, caching, no
autocomplete, and at most one request per second across an application's users.
For larger deployments use a self-hosted or contracted service. The backend's
online geocoder is disabled until explicitly configured; it does not silently
send destination text to a third party. The compatible JSON response is an array
of `display_name`, `lat`, `lon` strings. Providers with other formats or auth
contracts need an adapter, not just a URL substitution.

## Run

```sh
# Only in this managed workspace; use installed Qt normally on your computer.
source /workspace/toolchain/env.sh
export MACANOS_MAP_CACHE=/workspace/MacanOS/macanos/.runtime/osm-cache
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DOCTAVE_DEV_TOOLS=OFF
cmake --build build -j2
cmake -S macanos -B build-macanos -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build-macanos -j2
python3 macanos/scripts/run.py --profile macanos/.runtime/simulator
```

The normal desktop default profile is
`$XDG_STATE_HOME/MacanOS/simulator` (or `~/.local/state/MacanOS/simulator`).
The launcher uses `--sim --config <profile>`: first use seeds safe simulator
settings and three test tracks without overwriting an existing profile. Trips,
music and destination/unit preferences persist there. `boot_simulator()` without
a profile still makes an isolated temporary session for tests and captures.
Do not point simulator profiles at an OEM or real-vehicle installation.

The workspace toolchain defaults to offscreen rendering. On a normal desktop,
use the appropriate platform plugin and normal Qt installation as in the README.

Optional online search, **after reviewing the provider policy**:

```sh
export MACANOS_GEOCODER_URL=https://nominatim.openstreetmap.org/search
```

Alternatively use your own compatible HTTPS endpoint. No key is required by
public Nominatim. Do not put private/confidential destinations into public search.

Optional offline coverage, supplied under rights appropriate to your use:

```sh
export MACANOS_OFFLINE_TILES=/absolute/path/to/licensed-xyz
export MACANOS_OFFLINE_ATTRIBUTION='Copyright and licence supplied with your pack'
```

The directory must contain `z/x/y.png` in standard XYZ/Web Mercator, 256×256 PNG
format. Press Offline to use it. Missing tiles are explicitly unavailable. v0.3
has no download/import wizard and supplies no offline geographic pack. The unit
test pack is generated test imagery, not geographic coverage or a shipped map.

## Tests and evidence

```sh
ctest --test-dir build --output-on-failure -j2
ctest --test-dir build-macanos --output-on-failure
python3 macanos/tests/integration.py
npm test --prefix sdk/typescript
```

The service tests cover coordinate validation, destination proposal/acceptance,
saved-place/unit persistence, GPS expiry, actual HTTP parsing/rate limiting via a
local test server, and an owned offline tile fixture with zero network requests.
The interface tests exercise 30 role/page/resolution cases and actual search/share/
accept buttons. The real-process test restarts OCTAVE on the same profile, verifies
closed trip data directly in SQLite, browses its detail through the service, and
checks shared destination/units/media and independent frontend survival.

A one-off real public search for Ferry Building, San Francisco returned three
results. Actual OSM imagery was rendered in both captured windows. This does not
establish provider availability at other times or in the vehicle.

All available CTest tests and TypeScript tests were executed; exact results are
recorded with raw output in `docs/test-results/v03-*`. The optional upstream 3D
music-scene fixture requires a graphics backend beyond the software renderer and
remains a known failure; it is not part of the MacanOS map implementation.

Screenshots: [driver](screenshots/v03/driver.png),
[passenger](screenshots/v03/passenger.png). The default capture enables online maps
for the currently displayed demo viewport; do not run it as a tile harvesting job.

## Hardware and deployment limits

Physical GNSS/NMEA/gpsd, touchscreen mapping, Android multi-display APIs, factory
amplifier/MOST, automotive power and boot lifecycle remain unverified. The current
fix provider is simulated and labelled accordingly. Audio commands/metadata were
tested; audible output was not validated in this environment. All vehicle traffic
still passes the existing read-only ELM boundary; DTC clearing remains forbidden.
No deployment, publishing or merge was performed.

## Executed validation results

- Full backend and client builds succeeded with Qt 6.8.2 and GCC 14.2/C++17.
- Full upstream CTest: **58/59 passed**, 190.51 s. `tst_qmlfixtures` still fails
  its four optional Quick 3D music-device cases with the software renderer.
- Final API/service compatibility rerun: **4/4 passed**, 17.74 s, including
  generated API documentation and Go bindings.
- Final MacanOS CTest: **3/3 passed**, 13.95 s (client/recovery/policy, interface
  and new services). The interface suite covers 30 candidate layouts.
- Final actual two-process integration: **1/1 passed**, 6.324 s. It verifies
  persisted SQLite summaries and browsing after restart, shared destination,
  shared units/playback, DTC denial and independent frontend survival.
- TypeScript SDK: **7/7 passed** after regeneration; both SDK type generators
  and API JSON were updated for the additive navigation service.
- Qt Location runtime probe: `mapReady: true` after installing its OSM plugin.
  The initially missing plugin and missing private development headers were
  environment issues, not proof that Qt Location cannot render.
- One deliberate live public Nominatim evaluation returned **3 results** for
  Ferry Building, San Francisco. The shipped default has no geocoder endpoint.
- Both screenshots were captured from running QML clients with real OSM tiles;
  no illustrative map was substituted. Online tile download/cache behavior was
  verified, and offline pack loading was tested with owned generated fixtures.
- Python syntax compilation and Git whitespace checks passed.

Failures found and fixed during implementation included a media library
list-change feedback loop, stale-coordinate validation, compact trip-summary
text clipping, QML syntax errors, and a test dependency on the root build's
private settings headers. Failed intermediate builds/tests are not represented
as successes. No audible output or physical hardware validation is claimed.

Final screenshot review also found and fixed a cache-hit status notification: cached map imagery now updates the UI status without re-entering Image bindings. Client suites passed again after this correction.
