# MacanOS v0.4 — navigation and media integration

Local branch `macanos/v0.4` starts at `ea339dd` on `macanos/v0.3`. The two independent
Qt Quick clients, shared OCTAVE service, SQLite trip store, design system and
backend read-only diagnostics boundary remain. No factory controls or physical
vehicle interfaces were changed. Nothing was pushed, published or merged.

## Working functionality

Passenger Search accepts coordinates, saved places, or explicitly configured
online geocoding results. **Send to driver** creates a proposal; it sends no routing
request. Driver **Accept** approves the destination and asks an OSRM-compatible
router for road geometry, distance, duration and maneuver steps. **Dismiss** leaves
the current route alone. Both clients subscribe to the same backend route state.
Approval is a UI workflow on the trusted local service, not authentication of the
person in the driver's seat. Network pairing/remote authorization is out of scope.

The map draws the returned road geometry and current GPS position. Locate enables
follow mode; dragging disables it. Zoom and Target are display-local; Cancel clears
the shared route and stops its simulated replay. GPS accuracy is shown in meters.
Fixes expire after five seconds. Invalid/stale coordinates and accuracy worse than
100 m prevent route requests; stale/poor fixes suspend progress and hide ETA.
Off-route distance above 80 m produces a warning and hides the estimate. There is
no automatic reroute: cancel, search/share and approve again. Arrival below 25 m
remaining is reported. These are prototype thresholds, not validated automotive
navigation thresholds.

Progress uses nearest-segment projection on the returned geometry. Remaining
routing distance and duration scale by the geometric progress fraction. The UI
shows an estimated number of minutes and previews the next returned maneuver.
This is **basic simulated route following**, not validated turn-by-turn road
navigation: no voice, lane guidance, traffic, speed limits, map matching, reroute,
roundabout instruction grammar or road-closure handling is implemented. Long routes,
complex interchanges and self-intersecting routes have not been validated. The
parser bounds response size and geometry to 2 MiB / 20,000 points.

`LocationProvider` remains the physical GNSS boundary. The implemented simulator
replays an approved route at 10 m/s and stops at its end; without a route it runs
the existing local simulation. GPS and OBD simulator speeds are independent. Both
screens explicitly say **SIMULATED GPS**, the route says **SIMULATED**, and the
header says **SIM DATA**. No simulated location is presented as a physical vehicle
fix. There is no NMEA, gpsd, USB or Android GNSS driver yet.

Media uses OCTAVE's actual library/TagLib metadata and embedded artwork. Clients
subscribe to title, artist, album, source, cover revision, playback/progress and
shared volume. Covers use the existing safe loopback `/art` endpoint; no arbitrary
filesystem URL is sent to another process. The fallback graphic explicitly says
“No embedded cover.” Existing browsing/filtering, playback and volume controls
remain. Local tagged MP3 plus embedded PNG was exercised end to end; FLAC/M4A
parsers and other upstream media sources are retained, but their complete audio
and cover paths were not exercised here. Bluetooth/phone/streaming provider
metadata and authorization are not claimed integrated.

One backend `AudioOutputAdapter` owns output. The normal adapter uses Qt Multimedia;
an injectable silent adapter records volume writes for tests. Device loss remains
handled by the upstream output-selection path. Playback/volume and cover state
survive either display closing/reconnecting. “Output unavailable” is explicit when
there is no device. **Audible sound has not been verified** in this workspace.

## Renderer and provider decisions

| Option | Evaluation and decision |
| --- | --- |
| Existing Qt Quick raster viewport | Retained for Qt 6/Linux software rendering, independent display cameras and explicit cache policy. An original local raster color profile, **Macan Night v1**, provides dark surfaces, muted roads/water/parks and light labels. It does not add a renderer dependency. Raster recoloring has less semantic control/label quality than a native vector style. |
| Qt Location / OSM | The v0.3 Qt 6.8.2 runtime probe reached `mapReady: true`. It supports QML overlays, provider URLs and cache parameters. Still viable, but changing renderers is unnecessary for this vertical slice. Its Qt LGPL/GPL/commercial and provider terms apply independently. |
| CARTO dark hosted tiles | Reviewed the upstream style license. Hosted tiles require an enterprise plan or qualifying grant. They are **not** a free anonymous production/offline endpoint. No CARTO tile service or copied dark style is used. |
| MapLibre/native vector maps | Potentially better regional offline cartography and semantic dark styling. Not integrated or benchmarked. Requires compatible Qt integration, glyph/sprite/style/data licenses and graphics validation on the actual target. |
| OSRM-compatible routing | Implemented configurable HTTP adapter with validated GeoJSON route responses, timeout/error states, cancellation and one persistent cache. The public demo was evaluated with real road routes for screenshots/benchmark. Self-hosted OSRM is a future option; no routing engine or regional graph is bundled. |

Macan Night's original color profile in `macanos/styles/macan-night.json` is
**CC0-1.0**; its implementation is GPL-3.0-or-later. The profile is documented there
and implemented in `MapTiles::macanNight`. This dedication does not relicense map
data or third-party tiles. Standard online OpenStreetMap tiles use OSM data
(**ODbL**) and OpenStreetMap Carto cartography (**CC0**). Visible linked
`© OpenStreetMap contributors` attribution is retained, including compact layouts.
The local filter is not a new data source and does not remove provider obligations.

The public OSM endpoint requires no API key and has no availability guarantee.
Only the current viewport is requested: no region/zoom-stack prefetch, no bulk
download. Existing identifying User-Agent, two concurrent requests, bounded queue,
ETag/HTTP freshness and 100 MiB **raw tile** limit remain. Derived dark PNGs consume
additional disk space. Both displays share the disk cache; request coalescing
between processes is not implemented. Do not use public OSM tiles for offline
region downloads or production load without an appropriate provider plan.

Offline XYZ PNG packs must be supplied separately with permission for offline
use and their attribution. They retain their **native colors**, so supply a
licensed dark pack if dark offline maps are required. No geographic pack is
included. The online cache is not repurposed as an offline download pack.

OSRM engine code uses BSD-2-Clause; road data is generally OSM/ODbL. The evaluated
public demo URL needs no key, offers no SLA, and sends origin/destination to that
service. Do not assume its terms/capacity suit production. A commercial or keyed
provider needs a reviewed adapter/auth contract. No secret/API key is committed.
One route and its timestamp are persisted for 24 hours; reuse requires a new driver
approval, matching origin rounded to 0.001° and destination to 0.00001°. This is
limited cached replay, **not regional offline routing**. A restart restores the
target and preferences but never auto-approves/reactivates a route. Cache misses,
HTTP/invalid-response failures and absent configuration report unavailable.
Map connectivity and router connectivity are separate; disabling maps does not
turn off geocoding/routing. Each network service requires its own configuration.

## Build and run

Use the [desktop build instructions](../README.md). No Qt Location, vector renderer
or database dependency was added. Qt Multimedia is also required by the service
adapter tests. `ffmpeg` CLI is a test/capture/benchmark fixture dependency; regular
app playback does not require invoking this CLI.

```sh
# Managed workspace only; normal desktop installations use their Qt environment.
source /workspace/toolchain/env.sh
cmake --build build -j2
cmake --build build-macanos -j2

# Optional evaluated demo provider. Review its terms before enabling.
export MACANOS_ROUTER_URL=https://router.project-osrm.org/route/v1/driving/
# Optional place-name geocoding; coordinate/saved-place search works without it.
export MACANOS_GEOCODER_URL=https://nominatim.openstreetmap.org/search
python3 macanos/scripts/run.py
```

On Passenger Home: Search → enter `37.7955,-122.3937` → offline coordinate search
→ Send to driver. On Driver: Accept. Map on enables online map tiles; geometry
can still be shown without tile coverage. Locate follows GPS; Target centers the
destination. The route remains unavailable without a router endpoint or matching
cache. The launcher starts exactly one OCTAVE headless simulator and two clients.
Do not expose the trusted service port to an untrusted network.

| Configuration | Meaning |
| --- | --- |
| `MACANOS_ROUTER_URL` | OSRM base path ending `/route/v1/driving/`; HTTPS, or loopback HTTP for tests. Unset by default. |
| `MACANOS_GEOCODER_URL` | Nominatim-compatible explicit-search endpoint; unset by default. |
| `MACANOS_AUDIO_OUTPUT=null` | Silent test sink; use the normal Qt adapter for actual host audio. |
| `MACANOS_MAP_CACHE` | Writable raw/derived online cache directory. |
| `MACANOS_OFFLINE_TILES` | Licensed pack root with `z/x/y.png`. |
| `MACANOS_OFFLINE_ATTRIBUTION` | Required offline pack credit; the pack is ignored without it. |

For GPS-loss automation, `navigationManager.setSimulationPaused(true)` stops
simulator fixes; after five seconds clients mark them stale. `false` resumes.
`setRoutingOnline(false)` prevents new router requests (cache can still serve an
approved match). This is not a system network switch. Neither affects vehicle
controls. Default shared units remain mph and °F, with metric available.

## Validation and artifacts

```sh
ctest --test-dir build --output-on-failure -j2
ctest --test-dir build-macanos --output-on-failure
python3 macanos/tests/integration.py
npm test --prefix sdk/typescript

# Deliberate online viewport capture, not a tile harvesting tool:
MACANOS_AUDIO_OUTPUT=null python3 macanos/scripts/capture.py --route
MACANOS_AUDIO_OUTPUT=null python3 macanos/scripts/benchmark.py --seconds 15
```

Routing tests use a local HTTP server with synthetic/recorded OSRM JSON. They check
no request before approval, geometry validation, midpoint distance/duration,
arrival, off-route/accuracy/stale states, cancellation, offline cache hit/miss, and
restart without autoactivation. Interface tests cover 60 combinations: driver plus
five passenger pages at 1920×720, 1920×480, 1280×720, 1280×480 and 960×480, both
unavailable and active-route/pending-proposal states. Real QML button tests cover
search/share/accept/cancel and independent page/media state.

The real-process integration runs one OCTAVE and separate client processes. It
checks route handoff, GPS loss/resume, tagged MP3 metadata and actual `/art` PNG
bytes, shared volume, media/art re-subscription with either display closed,
backend restart, telemetry recovery, SQLite summaries/detail and forbidden DTC
clearing. The route service is a local fixture; live provider evaluation is
separate. No physical audio or GNSS claim follows from these tests.

Screenshots are actual Qt captures of an active simulated road route and original
embedded artwork: [driver](screenshots/v04/driver.png),
[passenger](screenshots/v04/passenger.png). Normal UI is event driven. The optional
`--render-metrics path` requests frames at 60 Hz **only for benchmarking** and writes
Qt render-signal/frame-swap timing at graceful application exit.

### Measured desktop performance

Final run: 15.03 s CPU/RSS sample, both clients at **1920×720**, active simulated
GPS route replay, real source tiles with warmed disk/derived caches, local tagged
MP3, silent output, Qt Quick software/offscreen. Regression jobs had completed.
The shared Linux host exposes three logical CPUs; scheduler contention from other
host workloads is not controlled. These numbers do not establish automotive
thermal margins, boot time, visible refresh rate or Android GPU performance.

| Process | CPU (% of one logical core) | Peak RSS (MiB) | Render signal interval p95 (ms) |
| --- | ---: | ---: | ---: |
| Backend | 6.12 | 60.68 | — |
| Driver | 19.36 | 78.57 | 2.49 |
| Passenger | 17.96 | 75.16 | 1.95 |

CPU is `/proc` process user+system time divided by sample wall time; 100% means one
core. RSS includes shared mappings and cannot be summed as unique memory. Render
time is the interval between Qt `beforeRendering` and `afterRendering`, excluding
other GUI/scene preparation, networking and presentation. Frame-swap interval p95
was 22.94 ms driver / 21.40 ms passenger. The benchmark requests a frame every 16 ms;
animations/updates can produce additional offscreen swaps (about 79.5 / 88.0 swaps
per second here). Those counts are **not physical display FPS or refresh rates**.
The normal application does not force continuous benchmark updates. A 15 s warm
cache run is not a cold-start, endurance or full-route performance test.

Machine-readable [results](v04-benchmark/results.json) and per-window
[driver timing](v04-benchmark/driver-render.json) /
[passenger timing](v04-benchmark/passenger-render.json) are committed. Reproduce with
the command above on the intended host before setting a deployment performance
budget.

## Remaining hardware and next milestone

NaviRider resolution, independent Android display access, Qt deployment/ABI,
touch routing, GNSS access, audio insertion/factory amplifier or MOST involvement,
CAN/OBD transport, protected automotive power, sleep/wake and thermal budget remain
unknown. A physical GNSS implementation must validate timestamp/accuracy/source
semantics at `LocationProvider`; a Linux-board audio adapter requires an actually
measured sink. No HDMI, USB, CAN or factory audio compatibility is assumed.

Next: select a production/self-hosted routing and map provider, validate longer
routes and cancellation/network-loss races, implement rerouting and clearer
maneuver instructions against recorded GNSS traces, then test a real host audio
sink. Follow with a read-only hardware interface inventory before any vehicle
connection. Factory controls remain outside scope.
