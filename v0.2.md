# MacanOS v0.2 cockpit redesign

## Review of v0.1

Reviewed the committed driver and passenger PNGs before implementation. The driver
layout gave a large circular RPM gauge roughly the same priority as navigation,
while speed sat in a separate column. Passenger Home was six equally weighted
telemetry cards, with media relegated to a bottom strip. Oversized surfaces,
repeated LIVE labels and a tall sidebar diluted hierarchy. Playback was shared,
but volume was a local-looking slider without backend-confirmed feedback.

## Implemented

- Driver: a bounded 200–250 px instrument column, prominent speed, compact RPM
  rail, coolant/trip status, dominant navigation concept and shared music panel.
- Passenger: Home combines music, navigation concept and a journey strip with
  working Media/Journey shortcuts. Detailed readings moved to Vehicle (page 4).
  Home/Media/Journey/Vehicle/Preferences tabs leave more space for content.
- Shared design system: `Tokens.qml`, `Type.qml`, themed panels/buttons and
  original procedural sleeve/navigation graphics. Charcoal surfaces, warm white
  type, muted secondary text, restrained red accents, 48 px controls, focus states
  and short button/RPM animations. No proprietary graphics or interface assets.
- Both clients subscribe to OCTAVE `volumeController.percent` and `muted` in
  addition to now-playing. Volume commands use `applyVolume` and its percent
  contract; UI feedback is backend-confirmed. Selecting a track or changing
  playback on either display updates both, without changing navigation state.
- `--width` and `--height` accept desktop window dimensions. Short layouts hide
  decorative sleeve art while retaining playback controls. No device connector,
  Android display API or screen-resolution claim is hardcoded.

## Candidate resolutions

Automated QML tests load the driver and all five passenger pages at 1920×720,
1920×480, 1280×720, 1280×480 and 960×480: 30 layout cases. They assert viewport and
visible panel bounds, driver instrument width and absence of QML runtime warnings.
These are design test candidates, **not verified NaviRider specifications**. The
prototype still needs physical DPI, touch-target and sunlight testing.

## Regression coverage

`macanos_interface` clicks actual QML buttons to verify next/play-pause dispatch,
shared now-playing bindings, Home→Media and Vehicle→Home navigation, independent
screen page state, and disabled/re-enabled controls on disconnection/recovery.
It uses a deterministic backend double; the separate Python integration launches
two real processes against real OCTAVE, verifies shared track and volume updates,
SQLite trip state, live telemetry, DTC denial, independent closure and restart
recovery. Existing client stale-value and transport-policy tests remain intact.

## Limits and next step

Navigation remains an explicitly labelled illustration, without routing/GPS or
route transfer. Shared interactions concern local media only. SQLite simulation
history remains temporary. No audible audio output, Android/NaviRider integration,
vehicle interface or physical display has been validated. Vehicle safety policy
was not changed. The optional upstream 3D fixture limitation recorded in the v0.1
report remains; this redesign uses 2D QML/Canvas and adds no 3D dependency.

Next: confirm actual screen dimensions and density, then implement a separate
navigation provider with explicit route ownership and passenger-to-driver handoff.
No publishing or merging was performed.

## Executed results

- Client and QML test targets compiled successfully with Qt 6.8.2/C++17.
- Client CTest: **2/2 passed** (8.60 s). Interface coverage includes 30 candidate
  role/page/resolution combinations, text/panel bounds, and interaction tests.
- Targeted upstream CTest: **7/7 passed** (28.55 s): ELM protocol, parameter store,
  trip recorder, OBD simulator/read-only policy, service bridge, now-playing,
  and volume controller.
- Real two-process integration: passed, including matching track title and 61%
  volume on both clients, SQLite trip identity, independent close and reconnect.
- Real Qt captures produced for both roles at 1920×720 and 1920×480.
- Python syntax compilation and `git diff --check` passed.

The entire upstream suite was not repeated for this QML/client-only change. Its
optional 3D fixture failure from v0.1 is not represented as fixed or passing.
